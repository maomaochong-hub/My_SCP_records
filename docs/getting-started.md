# 从零开始：配置、启动与上线

面向第一次接触这套代码的人。每一步都写了**为什么**，不只看操作。

---

## 0. 先花 30 秒搞懂它是什么

这不是一个「双击 index.html 就能看」的静态网页。它由两半组成：

| 一半     | 是什么                    | 在哪        |
| ------ | ---------------------- | --------- |
| **前端** | 你在浏览器里看到的东西：页面、动画、按钮   | `public/` |
| **后端** | 一个常驻的小程序，负责存数据、验密码、算统计 | `server/` |

浏览器**不允许**网页直接改硬盘上的文件，所以「在网页上编辑并永久保存」这件事，必须有一个后端在中间收下你的修改、写进 `data/db.json`，下次别人打开时再读出来。

所以顺序永远是：**先让后端跑起来 → 浏览器连上它 → 才能登录和编辑**。

几个后面会一直出现的词：

- **端口（port）**：一台电脑上有很多服务，端口号用来区分它们。这台机器上这个站固定住 `8787` 号门。
- **127.0.0.1**：指「这台电脑自己」。用它访问等于在本机内部敲门，不经过网络、不经过代理。
- **Cookie**：后端发给浏览器的一小段字符串，浏览器每次请求都自动带回来。登录状态就靠它，相当于一张「进门时发的手环」。
- **.env**：一个纯文本的配置文件，放端口、密钥、账号这类**不该写进代码**的东西。

## 1. 准备运行环

只需要 Node.js，**不需要** `npm install` 装任何依赖（这个项目零第三方库）。

```powershell
node -v      # 需要 >= 20，推荐 22
npm -v
```

检查通过就可以继续。

## 2. 配置 `.env`

### 2.1 复制模板

```powershell
cd M:/SCP
Copy-Item .env.example .env      # PowerShell
# cp .env.example .env           # bash / macOS / Linux
```

`.env` 已经在 `.gitignore` 里，**永远不会被提交到 GitHub**。这一点很重要：它里面是钥匙。

### 2.2 生成三个密钥

密钥就是「一串足够长的随机字符」，用来让密码哈希和会话无法被伪造。生成方法只有一条命令，**跑三次，得到三个不同的值**：

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

输出会类似 `K7fQ2m...`（43 个字符）。把三个值分别填给：

```ini
SESSION_SECRET=<第 1 次的结果>
AUTH_PEPPER=<第 2 次的结果>
STATS_SECRET=<第 3 次的结果>
```

**为什么必须是随机的？** 如果密钥是 `123456` 这种能猜到的值，别人拿到你的 `data/db.json` 就能自己算出密码哈希、伪造登录手环。随机 32 字节意味着穷举需要的时间超过宇宙年龄。

**三个能共用一条吗？** 技术上能，但不要。每个密钥负责一件事，共用等于把三道锁改成一把钥匙开三个门。

> ⚠️ **AUTH_PEPPER 只在「还没有账号」时随便改。** 一旦有了账号，改它会让旧密码全部失效（因为旧哈希是用旧 pepper 算的），必须重新执行第 3 步重置口令。所以：**先定好密钥，再建账号**。

### 2.3 填所有者账号

```ini
OWNER_EMAIL=you@example.com
OWNER_PASSWORD=至少10位的口令
```

这两个值只被第 3 步的初始化脚本读取一次，用来**创建**账号。建完之后改这里不会改密码（要改见 5.4）。

**为什么口令至少 10 位？** `scripts/seed.js` 会强制检查。短口令在离线暴力破解面前几乎等于没有。

### 2.4 本地开发用这几行

```ini
PORT=8787
NODE_ENV=development
PUBLIC_ORIGIN=http://127.0.0.1:8787,http://localhost:8787
STORAGE_DRIVER=file
COOKIE_NAME=scp_sid
COOKIE_SECURE=false
TRUST_PROXY=false
```

`PUBLIC_ORIGIN` **支持逗号分隔多个来源**（`localhost` 与 `127.0.0.1` 是两个不同的「源」，同名不同门牌）。写上两个，用哪个地址访问都能登录。

## 3. 建账号（只做一次）

```powershell
npm run seed
```

它会做三件事：创建所有者账号、写入几条示例内容、把数据文件初始化好。

看到 `所有者已存在` 是正常的——说明之前建过了，脚本会跳过，不会覆盖你的内容。

| 想做的事             | 命令                                                    |
| ---------------- | ----------------------------------------------------- |
| 首次建账号            | `npm run seed`                                        |
| 改口令（不改内容）        | `OWNER_PASSWORD=新口令 npm run seed -- --reset-password` |
| 重置全部会话（所有设备强制下线） | 同上，改口令会自动吊销                                           |

> PowerShell 里 `OWNER_PASSWORD=xxx npm run seed` 这种写法不合法，要写成：
>
> ```powershell
> $env:OWNER_PASSWORD="新口令"; npm run seed -- --reset-password; Remove-Item Env:OWNER_PASSWORD
> ```

## 4. 启动、打开页面

### 4.1 启动

```powershell
npm run dev      # 改代码自动重启，日常用这个
npm start        # 稳定运行，改了代码也不重启
```

成功的标志是终端里没有报错，并提示监听在 8787。

**如果报 `EADDRINUSE`**：上一次的服务没停干净。项目自带检查，会直接告诉你占用者的 PID 和结束命令；也可以换端口 `$env:PORT=8788; npm run dev`。

停止服务：在终端按 **Ctrl + C**。

### 4.2 打开

**<http://127.0.0.1:8787>**

> **一定用 `127.0.0.1`，不要用 `localhost`。** 你的机器上 `localhost` 可能被系统代理拦成 502；而且两者是两个不同的源，Cookie 不共享，混着用会「刚登录就掉线」。

### 4.3 页面地图

| 页面       | 地址          | 是什么                                                       |
| -------- | ----------- | --------------------------------------------------------- |
| **首页**   | `/`         | 大字 `S_C_P`、红色待删除标记、中央递归徽记 + `Per Aspera Ad Astra`、**有流星** |
| **次页**   | `/stage/`   | 同一套骨架，中央换成三个板块入口，**没有流星**                                 |
| **项目收集** | `/archive/` | 分类 + 条目，可检索                                               |
| **灵感写作** | `/writing/` | 浮动便签（上方）+ 网页创作（下方）                                        |
| **其他**   | `/other/`   | 预留占位                                                      |
| **访客统计** | `/stats/`   | 只有登录后能进，未登录会被弹回登录框                                        |

进站路径是：首页 →（点那句拉丁文）→ 次页 →（点板块）→ 内页。

## 5. 登录

### 5.1 操作

三种入口，效果一样：

1. 右上角 **「登录」** → 填邮箱 + 口令；
2. 访问 `http://127.0.0.1:8787/?login=1`，登录框自动弹出；
3. 直接访问 `/stats/`，会被 302 到 `/?login=1&next=/stats/`，登录后自动跳回。

成功后页面会**刷新一次**——这是正常的，前端需要按「所有者」身份重建界面（顶栏多出 统计 / 导出 / 退出，各页出现编辑按钮）。

### 5.2 为什么刷新

页面是纯静态的，服务端不负责拼 HTML。每次打开，前端先问一句「我是谁」（`GET /api/auth/session`），拿到身份后再决定显示什么。所以换身份必须重新加载。

### 5.3 原理，用人话说

整个流程四步：

1. **提交**：浏览器把邮箱和口令发给后端。
2. **比对**：后端用 `scrypt`（一种**故意很慢**的哈希算法）配合密钥算一遍，再和数据库里存的哈希比对。慢是为了让暴力破解变贵。
3. **发手环**：比对通过，后端生成一串随机 token，**数据库里只存这串 token 的指纹（SHA-256）**，真正的 token 只放进 Cookie。这样即使数据库被拖走，也伪造不出可用的 Cookie。
4. **验手环**：之后每个请求，后端读 Cookie → 查会话表 → 有效才允许写。前端的「隐藏按钮」只是好看，**真正的拦截在服务端**。

会话有效期：连续使用 7 天不掉线，但**最多 30 天**必须重新登录。改口令会立刻吊销所有设备。

### 5.4 改口令

```powershell
$env:OWNER_PASSWORD="新的至少10位口令"; npm run seed -- --reset-password; Remove-Item Env:OWNER_PASSWORD
```

### 5.5 登录不上，按这个顺序查

| 现象           | 原因                                                                      |
| ------------ | ----------------------------------------------------------------------- |
| 提示「邮箱或密码不正确」 | 邮箱要完全一致（大小写、空格）；口令是 `.env` 里那个，不是你记的别的                                  |
| 提示「来源校验失败」   | 访问地址和 `PUBLIC_ORIGIN` 不匹配。用 127.0.0.1 就把它也写进 `PUBLIC_ORIGIN`（支持逗号分隔）    |
| 登录成功但马上变访客   | `http` / `https` 混用、`localhost` / `127.0.0.1` 混用、或端口变了——Cookie 只认「同一个源」 |
| 生产环境怎么都登不上   | `COOKIE_SECURE=true` 但站点没有 HTTPS，Secure Cookie 会被浏览器直接丢弃                |
| 输入框都看不到      | 已经登录了（按钮会变成「退出」），或页面没加载完                                                |

## 6. 流星：怎么才会落

### 6.1 不需要任何操作

流星是**自动循环**的，只在**首页 `/`**。你什么都不用点，等就行。

| 参数        | 值                                                   |
| --------- | --------------------------------------------------- |
| 第一颗出现     | 打开页面约 2.2 秒后                                        |
| 小流星间隔     | 每次随机 2.6 – 6.2 秒                                    |
| 同时在飞的小流星  | 最多 3 颗                                              |
| 大流星概率     | 每次生成有 16% 的机会，但**同时只能有一颗**，且两颗间隔至少 20 秒             |
| 平均多久一颗大流星 | 约 25 – 45 秒                                         |
| 大流星会做的事   | 自带光晕；飞过中央那句拉丁文时**把文字照亮**再淡去；路上撞到小流星，小流星**立即消失**并闪一下 |

所以想看大流星：在首页**耐心等半分钟左右**，别急着点进次页。

### 6.2 看不到流星？按这个顺序排

1. **你在次页 `/stage/`** —— 那里**设计上就没有流星**。回首页看。
2. **系统开了「减少动态效果」** —— 这是最常见原因。代码检测到这个设置会**完全不生成流星**（尊重无障碍偏好，不是 bug）。
   - Windows：设置 → 辅助功能 → 视觉效果 → **动画效果** 打开
   - macOS：系统设置 → 辅助功能 → 显示 → **减弱动态效果** 关掉
   - 改完刷新页面。
3. **窗口太小或标签页在后台** —— 浏览器会暂停动画，切回来才继续。
4. **屏幕太暗** —— 流星很淡（骨白色，透明度低），亮度低或开了护眼模式会看不清。

### 6.3 自己验证它在工作

按 `F12` 打开开发者工具 → Console，输入：

```js
document.querySelectorAll('.meteor').length        // 当前有几颗在飞
document.querySelector('.meteor-field') ? '有流星层' : '没有流星层'
```

第一行随时间会出现 0 ~ 3 的变化，说明引擎在跑。

### 6.4 想调整频率

都在 `public/assets/js/modules/meteors.js` 顶部：

```js
const BIG_RATE = 0.16;      // 大流星概率
const BIG_COOLDOWN = 20000; // 两颗大流星最小间隔（毫秒）
const EAT_RADIUS = 52;      // 吞掉小流星的判定半径（像素）
const LIGHT_R = 380;        // 照亮文字的距离（像素）
```

小流星的生成间隔在同文件的 `rand(2600, 6200)` 处。改完保存，浏览器刷新即可（前端没有构建步骤）。

> 提醒：调大 `BIG_RATE` 会明显变吵。原来设计成「稀疏、克制」是有意的——流星是背景，不是主角。

## 7. 三个板块怎么用（一句一个重点）

- **项目收集**：先建分类再收录。删分类**不会删条目**，它们会落到「未分类」。检索覆盖 编号/名称/备注/域名，**备注写「一句话摘要 + 链接」**，以后一搜就有上下文。
- **灵感写作 · 便签**：**双击空白处**新建；**只能拖顶部标题栏**移动；标题和正文点进去就能改，停手约 0.6 秒自动保存（顶栏状态灯变绿即已落盘）。**删除没有回收站**。
- **灵感写作 · 网页创作**：HTML / CSS / JS 三标签 + 沙箱实时预览。停止输入只同步「草稿」，**`Ctrl/⌘ + S` 才是保存一个不可改的版本**。大改前先按一次。
- **访客统计**：今日 / 当月 / 总计 UV + 近 30 天柱状 + 月度归档。UV = 去重人数，PV = 浏览次数。所有者自己的访问默认不计 UV。

## 8. 买了域名之后

这是从「本地能跑」变成「别人能访问」的分界线。按顺序做，**第 2 条最容易漏，也是最容易导致「登录一直失败」的**。

### 8.1 域名解析

在域名控制台加一条 **A 记录**：`@` → 你的服务器公网 IP（想支持 `www` 就再加一条 `www`）。

- 生效通常几分钟，最长 24 小时。用 `ping yourdomain.com` 看解析到哪。
- **国内服务器（阿里云/腾讯云等）必须完成 ICP 备案**，否则 80/443 会被运营商拦掉，表现为「域名打不开但 IP 能开」。

### 8.2 必须上 HTTPS（不是可选项）

原因很具体：登录 Cookie 带 `Secure` 属性，**只在 HTTPS 下才会被浏览器保存**。用 http 访问，登录永远失败、而且看不出错在哪。

最省事的是用 Caddy 或 Nginx + Let's Encrypt 自动签证书。证书要能自动续期（90 天过期）。

### 8.3 改 `.env`（生产环境）

```ini
NODE_ENV=production
PUBLIC_ORIGIN=https://yourdomain.com,https://www.yourdomain.com
COOKIE_NAME=__Host-scp_sid
COOKIE_SECURE=true
TRUST_PROXY=true
```

逐条说为什么：

- **`NODE_ENV=production`**：开启生产校验，启动时会检查密钥是否还是默认值；Cookie 名自动切到 `__Host-` 前缀（这是浏览器强制的最严格 Cookie：必须是 HTTPS + 路径为 `/` + 不带 Domain）。
- **`PUBLIC_ORIGIN`**：写**你的域名**，不是 IP。写错了所有写操作都会被 CSRF 校验挡成 403。多个域名（带/不带 www）用逗号隔开。
- **`COOKIE_SECURE=true`**：配合 HTTPS，否则登录不生效。
- **`TRUST_PROXY=true`**：请求经过 Nginx/CDN 转发时，真实访客 IP 在 `X-Forwarded-For` 头里。**不开这个，所有访客会被记成同一个 IP，统计直接失真。**

### 8.4 反向代理要转发这两个头

```nginx
location / {
  proxy_pass http://127.0.0.1:8787;
  proxy_set_header Host $host;
  proxy_set_header X-Forwarded-Proto $scheme;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

漏 `X-Forwarded-Proto` 会让后端以为你在用 http，于是 Secure Cookie 又出问题。

### 8.5 安全收尾清单

- [ ] 防火墙只开 **80 / 443**，**8787 绝对不要暴露到公网**（这个端口没有 HTTPS，等于明文）。
- [ ] 三个密钥在生产环境**重新生成**（和本地不同）。
- [ ] `.env` 权限收紧，只给运行账号读。
- [ ] 确认 `git status` 里**没有** `data/` 和 `.env`。
- [ ] 配一个定时备份：每天 `cp data/db.json` 到别处，或定期点顶栏「导出」。

### 8.6 关于隐私

访客统计**不存明文 IP**，只存 `HMAC(ip)` 的前 16 个字符——能区分「是不是同一个人」，但反推不出 IP。这是刻意的设计。如果开了 `STATS_EXCLUDE_OWNER=true`，你自己的访问不算 UV（想自测就临时改成 `false`）。

## 9. 故障对照表

| 现象                   | 多半是                                      |
| -------------------- | ---------------------------------------- |
| `EADDRINUSE :::8787` | 上次服务没停。按提示杀进程，或换端口                       |
| 页面 502               | 用了 `localhost` 且本机有代理。改 `127.0.0.1`      |
| 页面 404               | 后端没启动，或访问了不存在的路径                         |
| 登录 403「来源校验失败」       | `PUBLIC_ORIGIN` 与当前地址不一致                 |
| 登录成功但没登录上            | http/https 混用、源不一致、`COOKIE_SECURE` 与协议冲突 |
| 改了内容刷新没了             | 自动保存 0.6 秒内关掉了页面，等状态灯变绿                  |
| 便签两个标签页互相覆盖          | 同一条便签只在一个标签页里改（保存是整体覆盖）                  |
| 统计数字不涨               | 你自己在看，`STATS_EXCLUDE_OWNER=true` 不计 UV   |
| 手动改 `db.json` 后无效    | 服务在跑，内存副本把它盖回去了。**先停服务再改**               |
| 看不到流星                | 在次页 / 系统开了减少动态效果 / 窗口在后台                 |

## 10. 附录：几个概念的一次性说清

**哈希（hash）**：把任意长度的输入变成固定长度的一串，且**不可逆**。所以密码存的是它的哈希，你忘了只能重置，不能「找回」。

**加盐 / 慢哈希（scrypt）**：给每个密码加一段随机盐再算，防止「彩虹表」批量破解；故意算得慢（几十毫秒），让穷举变贵。

**cookie 与 session**：Cookie 存在你的浏览器里，Session 存在服务器上。Cookie 里只是「手环编号」，真正「这个人是谁、有什么权限」记在服务器的花名册上。所以服务器重启、会话过期，手环就废了。

**CSRF**：别的网站偷偷拿你的身份发请求。防御办法是要求请求带一个自定义头、并且来源（Origin）必须是本站——跨站表单做不到这两件事。

**UV / PV**：UV 是「多少人」，同一个人一天只算一次；PV 是「看了多少次」，刷新就加一。前者衡量规模，后者衡量黏性。

**为什么 `data/db.json` 是唯一真相**：整个站的内容只存在这一个文件里（`STORAGE_DRIVER=file` 时）。它被原子写入（先写临时文件再改名），所以断电不会写坏；但**它丢了就等于全丢了**。这就是为什么「导出」按钮和定时备份不是可选项。

## 最短上手路径（15 分钟）

1. `node -v` 确认 ≥ 20
2. `cp .env.example .env`，生成三个密钥填进去，填邮箱和口令
